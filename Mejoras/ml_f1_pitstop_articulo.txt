MEDIUM — PLAN DE MEJORA DEL ARTÍCULO (AJUSTE FINAL)
=====================================================

PROPÓSITO
---------
Convertir el artículo en una pieza técnica profesional, precisa y legible.
El artículo NO debe exagerar el alcance, presentar el dataset como telemetría real,
vender HGB como "interpretable" o confundir un experimento de portafolio con
producción industrial.

La historia central debe ser:
    "La validación correcta y el diseño de features explicaron la mayor parte del
     rendimiento; después de cierto punto, añadir complejidad dejó de aportar una
     mejora convincente."

======================================================================
P0 — CORRECCIONES FACTUALES OBLIGATORIAS
======================================================================

P0.1 — SEPARAR V0/V1 DE LA HISTORIA DE FEATURE ENGINEERING
----------------------------------------------------------
No decir: V0 ~0.89 -> V1 ~0.86 si se comparan estrategias de validación.
Usar los valores reales del experimento de validación:
- V0 random split ≈ 0.844
- V1 group-aware ≈ 0.815

Interpretación: el split aleatorio era optimista porque compartía estructura de
race event entre train y validation. Después, en sección distinta, mostrar cómo
E13 lleva el rendimiento a ~0.860.

No mezclar el efecto de validación con el efecto de feature engineering.

P0.2 — CORREGIR BASELINES
-------------------------
Mantener separados:
E10 / raw:
- Dummy ≈ 0.500
- Logistic Regression ≈ 0.732
- HGB ≈ 0.815

E13 / engineered:
- Logistic Regression ≈ 0.777
- HGB ≈ 0.860
- ExtraTrees ≈ 0.829

E20:
- tuned HGB = 0.8611

No usar LR=0.777 como baseline raw.

P0.3 — CORREGIR E11 / E12 / E13
--------------------------------
Valores coherentes con los artefactos:
- E10 raw ≈ 0.815
- E11 + basic/domain ≈ 0.858
- E12 corrected temporal ≈ 0.844
- E13 full safe ≈ 0.860
- E20 tuned ≈ 0.8611

Si se cuenta el experimento fallido, etiquetar por separado el E12 ingenuo/fallido
≈ 0.792 y no sustituir con él el valor del E12 corregido.

P0.4 — NO PRESENTAR `LapTime` COMO LEAKAGE
------------------------------------------
`LapTime (s)` no se eliminó por leakage, sino por inestabilidad/outliers.
Separar:
A. Features excluidas por semántica/leakage no certificable:
   RaceProgress, LapTime_Delta, Cumulative_Degradation, Position_Change
B. Feature temporalmente válida pero inestable:
   LapTime (s)

P0.5 — ELIMINAR FEATURES INEXISTENTES
-------------------------------------
No mencionar "fuel load" ni "weather".
Describir el dataset con:
Driver, Compound, Race, Year, PitStop, LapNumber, Stint, TyreLife, Position,
LapTime y features derivadas temporales.

P0.6 — ELIMINAR CUALQUIER RATIO DE TIEMPO (5x) Y ADMITIR LA ASIMETRÍA
----------------------------------------------------------------------
No usar ningún ratio de tiempo (ej. "5x faster") en el artículo.
Añadir explícitamente:
"El coste de búsqueda de E20 (RandomizedSearchCV) no fue instrumentado en tiempo
de ejecución desde el inicio, por lo que cualquier comparación de tiempo de
entrenamiento entre E20 y AutoGluon sería metodológicamente asimétrica.
La comparación justa entre ambos se limita a footprint en disco y latencia de
inferencia, donde el HGB es sustancialmente más ligero."

Lenguaje seguro:
"Once selected, the HGB candidate had a substantially smaller operational
footprint than the AutoML ensemble under this benchmark."

P0.7 — ELIMINAR "COMPLETELY INTERPRETABLE"
------------------------------------------
No usar: fully interpretable, completely interpretable, Interpretable = Yes.
Usar: easier to inspect and audit, single-model pipeline, lower model complexity,
global inspection via permutation importance.

P0.8 — CORREGIR LA CONCLUSIÓN SOBRE FEATURE ENGINEERING
--------------------------------------------------------
No usar como regla universal: "Feature Engineering > Algorithm Choice".
Usar: "In This Experiment, Feature Design Mattered More Than Model Choice".
Texto seguro: "Within the model families actually evaluated, feature design
contributed substantially more predictive lift than subsequent tuning or model
switching."

P0.9 — CORREGIR "NO OVERFITTING"
--------------------------------
No decir "no overfitting!".
Usar: "Performance did not degrade on the frozen temporal holdout (0.8727 vs CV
0.8611 ± 0.0251), providing no evidence of material generalization collapse under
this evaluation."

P0.10 — PERMUTATION IMPORTANCE NO ES CAUSAL
-------------------------------------------
No decir: "this is what an F1 strategist cares about".
Usar: "Within this synthetic dataset and fitted model, stint state, tyre life and
pit history carried the strongest predictive signal. Permutation importance
measures model dependence, not causal importance."

P0.11 — EXPLICAR AUTOGLUON CON JUSTICIA
---------------------------------------
Añadir: "Both approaches were evaluated on identical group-aware outer folds.
AutoGluon retained its own internal model-selection procedure inside each training
fold, and that internal split was not group-aware."
Eliminar "AutoGluon wins on nothing". Usar: "Under this dataset, feature set and
external validation protocol, the added AutoML complexity produced no measurable
predictive improvement over E20."

P0.12 — CORREGIR KAGGLE TOP-2
-----------------------------
Verificar y corregir winner score, second-place score y margen ~0.00001.
No usar "probable V0". Usar: "validation protocol not fully specified in the
public writeup". No presentar a los ganadores como metodológicamente inferiores.

P0.13 — ELIMINAR "MODEL IN PRODUCTION"
--------------------------------------
Usar: selected final model, final candidate, model carried forward.
No usar: production model, deployed model, ship (salvo como hipótesis futura).

P2 — QUÉ MOSTRAR Y QUÉ NO MOSTRAR
======================================================================

P2.1 — MÁXIMO 2 FIGURAS PRINCIPALES
-----------------------------------
Figura 1 (Validation split effect):
- V0 vs V1 sobre el mismo modelo/features.
- Objetivo: hacer visible el optimismo del split ingenuo.

Figura 2 (Evolución del rendimiento y retornos decrecientes):
- Eje X: E10 → E11 → E13 → E20 → AutoGluon → XGBoost → CatBoost → Ensemble.
- Eje Y: ROC-AUC.
- Añadir barras de error (std dev de los folds) para E20 y los challengers.
- Objetivo: mostrar que el salto vino de las features, y que la complejidad
  adicional (Ensemble, etc.) cae dentro del ruido del modelo.

Eliminar del scope principal: calibration curve, heatmap circuito x año, ROC
comparativa sobre holdout, complexity score inventado.

P2.2 — "WHAT I REJECTED" SIN SENIORITY THEATER
-----------------------------------------------
Si se incluye, usar solo decisiones experimentales reales:
- unstable rolling feature;
- additional ensemble complexity;
- reopening the holdout.
No incluir "MLOps completo" como si hubiera sido un experimento descartado.

======================================================================
CONCLUSIÓN FINAL RECOMENDADA
======================================================================

Idea central:
"This project did not show that manual ML is universally better than AutoML.
It showed something narrower and more useful: under a fixed, leakage-aware
validation protocol, most of the predictive gain came from problem framing and
feature design, while additional model complexity produced diminishing returns."

Añadir:
"The final result was not only a selected model, but a documented reason for
why further optimization was not justified under the experiment's scope."

No usar: "production-ready", "enterprise", "absolute traceability",
"model governance system" o "decision system".
